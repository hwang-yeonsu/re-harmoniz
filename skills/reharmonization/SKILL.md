# reharm:reharmonization — Evolution Session (5 Phases, One Cycle)

**Read `${CLAUDE_SKILL_DIR}/../../EVOLUTION.md` (the protocol, at the plugin root) and follow §1 (the goal/decision block), §4 (protocol), §5 (adversarial rubric incl. §5.1 depth), §6 (web policy), §7 (evaluation), §11 (templates) exactly.** This skill is the entry point; the protocol is the engine. On conflict, EVOLUTION.md wins.

**One session serves one open decision.** The decision decides what gets targeted, how deeply it is judged, and what gets cut — that ordering is the difference between research and note-grading.

## Procedure (summary of §4)

1. **Resolve the scope**, read scope `CLAUDE.md` — including its `### Goal & Open Decisions` block (§1). No decisions declared → say so, recommend declaring them (`reharm:pushing` row 2), and if the user proceeds anyway, run unfiltered and record in the report that relevance was not filtered.
2. **Phase A — Retrospect**: read the latest `wiki/meta/evolution/E####.md` + `hot.md`; adversarially re-verify last session's changed nodes; **for mashups carrying `borrowed:` (§2), compare each donor node's current status/generation against the snapshot — drift is a new objection to absorb** (a donor that is now `pruned` counts as drift too). Roll back or demote collapses. Start from failing checks if the last `E####.eval.json` failed.
3. **Phase B — Target Selection (decision first, then node)**: ① pick the **active decision** — one open decision → it is active; several → present each with its state (serving nodes, how many `hardened`+, what it waits on) and let the user choose ② frontier inside it: `python3 "${CLAUDE_SKILL_DIR}/../../scripts/boundary-score.py" --json --top 5 --serves <ID>` from the scope root (it reads `./wiki/`) ③ decay candidates **among that decision's serving nodes**: compare frontmatter `last_challenged` against the §3 cadence — nodes bearing on no open decision are *not* decay candidates, they are prune candidates ④ user-named topics first. **Present the merged candidates and let the user choose — never auto-select.**
4. **Phase C — Mutation**: decompose new `.raw/` material into existing nodes; **field-origin results (`.raw/experiments-results/`) import into the target's `## Field Evidence` with their conditions — not into Objections; external material is seed (§4)**; hunt evidence/counterexamples via web search within §6 bounds — **decision angle first, and for a single-depth target that angle only** (§6.1); contrast adjacent nodes → `mashups/`. **Owner design decisions (`.raw/design-decisions/`)** are absorbed *and* checked against the decision block: report which declared decisions the material just settled.
   Then the **prune sweep (§4 Phase C, every session, before Phase D spends anything)**: report as one batch — never auto-apply — every node whose `serves:` is empty with no open decision depending on it (start from the lint `unassigned_claims` list), whose served decisions are all `settled`, or whose branch an absorbed design decision just collapsed. Same walk covers the experiment queue: for each non-`retired` `type: experiment` node, re-read its `## Decision at stake` and report any whose two branches collapsed into one outcome. The user picks what flips to `status: pruned` / `retired`.
5. **Phase D — Natural Selection, at the depth each node earns (§5.1)**: decide depth per target first — **full** (load-bearing for the active open decision: flipping it changes which way the decision goes) → three lenses; **single** (serves an open decision but is not load-bearing) → one lens derived from `evidence_class` (`literature`→`evidence`, `field`→`reproducibility`, `design`→`coherence`, absent→`literature`); **none** (bears on no open decision) → do not judge it at all, report it as a prune candidate and drop it from the session.
   Spawn each lens as an **isolated refuter sub-agent** (refutation is the default). Resolve the **absolute** paths of the worker doc (`${CLAUDE_SKILL_DIR}/refuter.md`) and `EVOLUTION.md` (`${CLAUDE_SKILL_DIR}/../../EVOLUTION.md`) — e.g. with `realpath` — and spawn each sub instructed to "read `<abs refuter.md path>` and follow it," passing inline: its one lens, the target node verbatim (frontmatter + body), the cited `wiki/sources/` page originals, and the lens material refuter.md lists. **Never pass the session's mutation narrative** (§5 isolation), **and never tell a refuter which depth it is running at** — a lens that knows its verdict is decisive judges differently, and the worker is deliberately kept blind to everything but the artifact.
   Full depth passes on ≥2/3 survival; single depth passes iff its one lens returns `refuted: false`. On a pass: `challenges_survived +1`, refresh `last_challenged`, and **at full depth only** `generation +1` plus promotions proposed per §3 (the developing→hardened currency is class-calibrated — §2 `evidence_class`; a single-lens pass never opens that gate). Partial collapse → absorb into `## Objections & Limits` by **rewriting the section to the current set** (§2: compress each objection to its ≤2-line boundary condition; the refuter's full reason is archived in the E#### report), revise, **re-spawn the same lens workers once** to re-judge — **one re-judge round per node per session (§5.3)**; a node still collapsing after it keeps its generation, keeps the residual objection, and its unresolved part is filed as a `questions/` node. Total collapse → `status: deprecated`. If spawning is unavailable, degrade to sequential in-context judgments and record `refuters ran non-isolated` in the E#### report (§5 fail-loud).
6. **Phase E — Record**: write `E####.md` report (§11.1 template **and its length discipline**: target ≤40 lines; `decision:` in frontmatter, verdicts one line per node **opening with the depth**, reason clauses only for refuted lenses and re-judgings, a `## Pruned` line per cut, and `## Decision movement` — settled / closer + what remains / unmoved + why) → overwrite `hot.md` → update `index.md` (§11.2: the Decisions table first, then the census incl. `pruned`, then the node rows with their `Serves` column) → prepend a **one-line** `log.md` entry → lint via `python3 "${CLAUDE_SKILL_DIR}/../../scripts/wiki-lint.py" --json` from the scope root (findings → `wiki/meta/lint/`) → write `E####.eval.json` (§7 schema v3: `decisions_settled` and `branches_pruned` alongside the secondary counters, plus the stagnation verdict).

## Constraints

- One session = one cycle = one scope = one active decision. No multi-scope evolution.
- **Never spend refuters on a node no open decision rests on.** Report it as a prune candidate instead (§4 Phase C). Three sub-agents to grade something nothing is waiting on is the failure this protocol version exists to remove.
- **Depth is derived, never negotiated** — it follows the node's role in the active decision (§5.1), and it is re-derived each session because a decision settling or reopening changes what rests on what. Record it in the report so cheap verdicts are auditable.
- Pruning and promotion are both **proposed, never applied automatically** (§3). The user picks.
- No change history inside node bodies — process belongs to the report, results to the node. A conditional recommendation *is* a result and belongs in the body; a plan does not (§2).
- Never modify `.raw/`. Never create branches, PRs, or git tags — the repo's auto-commit owns git history; the `E####.md` report is the session boundary.
- Verification is allowed to take long — do not rush Phases A and D. But do not confuse *long* with *repeated*: the §5.3 re-judge cap is a hard stop, not a suggestion.
