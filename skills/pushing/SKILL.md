# reharm:pushing — Next-Step Advisor (read-only)

The anticipation beat — like *pushing* a note ahead of the bar, this looks at where a scope stands **relative to the decisions it exists to settle** and calls the next move before you have to ask: declare the goal, seed (`root`), evolve (`reharmonization`), resolve ambiguity or prune dead branches (`critique`), design the experiment (`experiment-design`), escalate stuck evidence (§13 deep research), answer the decision (`ensemble`), or borrow across scopes (`modal-interchange`).

**This is the only read-only skill: it inspects and recommends, never writes a file, never runs another skill.** That preserves the protocol's contract — nothing is auto-decided; you pick the targets and adjudicate (EVOLUTION.md §3, §4 Phase B). **Read `${CLAUDE_SKILL_DIR}/../../EVOLUTION.md`** for the state definitions it reads: §1 (the goal/decision block and `serves:`), §3 (maturity, pruning, re-verification cadence), §5.1 (verification depth), §7 (session evaluation + stagnation).

## Procedure

1. **Resolve the scope** (`.raw/` + `wiki/` present). If the cwd is not a scope, take the path from arguments or ask once. If no scope exists at all → recommend `reharm:root` and stop.
2. **Gather state** — every signal already exists (§8); all reads, no writes:
   - **Decisions (§1)**: the `decisions` block in the lint JSON below — `declared`, `open`, `settled` — plus the decision text from the scope `CLAUDE.md`. **This is the frame for everything else**: a recommendation that cannot name the decision it serves is not prioritization.
   - **Health**: `python3 "${CLAUDE_SKILL_DIR}/../../scripts/wiki-lint.py" --json` from the scope root. Read `clean`, `counts` (`contradictions`, `orphans`, `dead_wikilinks`, `missing_frontmatter`, `duplicate_stems`), and the goal-binding warnings (`no_decisions_declared`, `duplicate_decision_id`, `unknown_serves_target`, `stale_serves_target`, `unassigned_claims`, `prune_without_restore_point`).
   - **Frontier, per open decision**: `python3 "${CLAUDE_SKILL_DIR}/../../scripts/boundary-score.py" --json --top 5 --serves <ID>` from the scope root, once per open decision. Positive-`score` pages are evolution-ready (outward-pointing, recently touched). Each row also exposes `status` / `generation` / `challenges_survived` / `sources_count` / `serves`. Drop `--serves` only when no decisions are declared.
   - **Census**: `status_census` in the lint JSON — the **computed** node totals per status (claims + mashups), including `pruned`. The `**Census:**` line in `wiki/index.md` is display-only; a `census_drift` warning means the display line needs a refresh, never that the census signal is wrong.
   - **Prune queue (§3)**: the lint `unassigned_claims` list, plus nodes whose `serves:` names only `settled` decisions (read `serves` from the boundary-score rows). Candidates, never verdicts. Note `boundary-score.py` excludes already-`pruned`/`deprecated` nodes from the frontier by default — pass `--include-terminal` only when auditing what was cut.
   - **Re-binding queue (§1)**: the lint `stale_serves_target` list — nodes bound to a `superseded` decision. **Separate from the prune queue**: the question was replaced, not answered, so these need re-pointing at the successor before anything is cut.
   - **Last session**: the newest `wiki/meta/evolution/E####.eval.json` — `pass`, `stagnation.verdict` (`continue` / `reseed` / `change-strategy`), and the decision counters (`decisions_settled`, `branches_pruned`) when present (§7 v3).
   - **Decay**: node frontmatter `last_challenged` vs the §3 cadence (seed/developing every session, hardened 4 weeks, evergreen 12 weeks) — **counting only nodes that serve an open decision**; nodes bearing on no open decision are outside the calendar (§3) and belong to the prune queue instead. Scopes are small — read dates directly, no script.
   - **Unprocessed material**: `.raw/` files (recursively) with no matching `wiki/sources/` page.
   - **Stuck at the evergreen gate**: `status: hardened` nodes whose `## Field Evidence` is empty (filter by frontmatter status, then read just those bodies); plus `evidence_class: field` `developing` claims short of the §3 replication currency (<2 Field Evidence entries) with no `planned`/`running` experiment. Only the §2 code workspace can produce the real-world result they need.
   - **Stuck at the evidence gate (§13)**: **literature-class** `status: developing` claims that are **load-bearing for an open decision** (§5.1) with `sources_count` < 2 and no new independent source in the last 2 `E####.md` reports; plus `status: open` questions with no progress across the last 4 reports. Only signal-worthy when the scope `CLAUDE.md` sets `Research escalation:`. (Field-class claims route to the experiment signal above — more searching cannot replicate a measurement.)
   - **Answerable decisions (§14)**: per open decision — does it have ≥1 load-bearing claim at `hardened`-or-above, no unresolved contradiction among its serving nodes, and no `planned`/`running` experiment that would change the verdict? Then look in `wiki/deliverables/` for a page whose `question:` is that decision ID (or its question node) and compare its `updated` against the newest `E####.md` date.
   - **Borrowed drift**: mashups carrying a `borrowed:` snapshot (§2) whose donor node's **current** status/generation no longer matches it — read the donor scope's frontmatter directly (a demoted, deprecated, or pruned donor means the mashup's premise moved).
   - **Sibling scopes**: count sibling directories that are also scopes (for the modal-interchange signal).
3. **Apply the cascade** — first match wins; surface lower matches as secondary candidates so the user sees the whole board:

   | # | Condition | Recommend |
   |---|---|---|
   | 1 | no scope / 0 evolving nodes | `root` — seed first |
   | 2 | lint `no_decisions_declared` (evolving nodes exist, no `### Goal & Open Decisions` block) | **declare the goal** — edit the scope `CLAUDE.md` per §1/§10: one `\| ID \| decision \| open \|` row per decision the scope exists to settle. Nothing below can be prioritized honestly without it, because every other signal is measured against the decisions. Read-only: say what to write, never write it |
   | 3 | `.raw/` material not yet atomized | `root` — atomize new material, decision-gated (§1), before evolving |
   | 4 | lint `clean:false` (contradictions, dead links, orphans, missing frontmatter) **or** `questions/` backlog **or** low-confidence nodes stalled ≥2 sessions | `critique` — clear structural/ambiguity debt before evolving |
   | 5 | last `eval.json` `pass:false` **or** borrowed-snapshot drift on a mashup | `reharmonization` — integrity first: Phase A resumes failing checks and absorbs borrowed drift before anything new is frozen or evolved |
   | 6 | an open decision is **answerable** and its deliverable is absent or stale (§14) | `ensemble` — **the decision can be taken now.** Answering it is the highest-value single action and it names which branch needs the next session. One action; no node state changes |
   | 7 | prune queue non-trivial — `unassigned_claims` ≥ 3, **or** any node whose served decisions are all `settled`, **or** any `stale_serves_target` | `critique` — run the prune sweep (§3, §4 Phase C): flip the dead branches to `pruned`. The cheapest action on the board, and the only one that makes every later session cheaper. If the trigger was `stale_serves_target`, say so plainly — that queue gets **re-bound to the successor decision** (§1), not cut, and doing it in the wrong order deletes branches for a question that was replaced rather than answered |
   | 8 | `status: hardened` node(s) with empty `## Field Evidence` (stuck at the evergreen gate), or field-class `developing` claim(s) short of the §3 replication currency with no live experiment | **design the experiment** — `reharm:experiment-design` pre-registers it (hypothesis + a `## Decision at stake` pair + a CONFIRM/REFUTE criterion, all fixed before the run, §12). **This row is an occasion, not a verdict**: the design skill runs the decision gate first and will redirect back here if no outcome would change an action outside the wiki — an empty `## Field Evidence` is a reason to *consider* an experiment, never a reason to have one. If a `planned`/`running` node already exists for the claim, point at its handoff instead of re-designing. Read-only |
   | 9 | scope `CLAUDE.md` sets `Research escalation:` **and** (a **literature-class** `developing` claim load-bearing for an open decision, stuck < 2 independent sources with no new independent source for ≥2 sessions, **or** an `open` question with no progress for ≥4 sessions) | **escalate to deep research** (§13) — recommend the DESIGN step: flip the question to `status: escalated` + write its `## Escalation` block ("what would change our mind"), typically via `reharm:critique`; the user runs the external tool named by the toggle and its report returns through `.raw/deep-research/` → `reharm:root`. **Manual-only: the autonomous loop template skips this row.** Read-only |
   | 10 | stagnation `verdict:"change-strategy"` | `critique` — rethink targets, not the same loop. When the trigger was §7's third case (generations gained, no decision moved), say so plainly: the wiki is hardening things no decision is waiting on, and the fix is re-reading the decision block, not another verification round |
   | 11 | stagnation `verdict:"reseed"` (counters flat, no new seeds/sources) | `root` — needs new raw material, not more churn |
   | 12 | positive-score frontier **inside an open decision**, **or** decision-serving nodes past their §3 cadence | `reharmonization` — momentum: evolve the active decision's frontier, re-verify decayed nodes |
   | 13 | ≥2 scopes and nothing above fired | `modal-interchange` — optional cross-scope mashup |
   | 14 | nothing pending | report **current**; show the soonest next re-verification date and where each open decision stands |

   **Why this order.** One principle: **anything that realizes value already earned, or that lowers the cost of every later session, outranks anything that adds work.** So the answerable decision (6) and the prune sweep (7) sit above momentum (12) — and so do the stagnation verdicts (10, 11), which exist precisely to stop the loop from repeating itself.

   That is a deliberate reversal of the pre-1.0.0 order, where momentum sat third-from-top with everything else below it. The frontier/cadence pair is near-always on in a living scope (seed/developing nodes re-verified *every session*), so synthesis, both stagnation verdicts, and modal-interchange were effectively unreachable in the autonomous loop, which takes the cascade's first match: a scope could harden nodes indefinitely and never produce the answer it had already earned. Rows 4–5 still outrank everything below them — synthesizing an answer or freezing a criterion on top of an unsound last session (§4 Phase A debt) propagates the fault. The one-live-experiment-per-claim rule (§12) keeps row 8 from monopolizing: while its experiment is `planned`/`running`, the row only points at the existing handoff.

4. **Report** in the user's language: **the decision at stake**, the recommended skill, the **evidence** (the specific counts / candidate pages / verdict that triggered it), the exact command to run next, and any secondary candidates. Add one line per open decision on where it stands (serving nodes, how many at `hardened`+, what it is waiting on). Then stop — the user runs the chosen skill.

## Constraints

- **Read-only. Writes no file, edits no node, runs no other skill, touches no git state.** It is a recommendation, not an action — the user always chooses (EVOLUTION.md "nothing is auto-decided"). Row 2 recommends *what to write* in the scope `CLAUDE.md`; it does not write it.
- **Name the decision, or say there is none.** Every recommendation states which declared decision it serves. If the scope declared none, row 2 fires and the answer is to declare them — do not rank by frontier score and present that as prioritization.
- **One scope per run** (mirrors reharmonization). Cross-scope comparison is `modal-interchange`'s job; pushing only *suggests* it when ≥2 scopes exist.
- **No new state file** — it derives everything from the two stdlib scripts plus `index.md` / `E####.eval.json` / frontmatter / the scope `CLAUDE.md`. If `wiki/` is missing, say so and recommend `root`.
- If two branches tie, present both and let the user pick — do not force a single answer.
